UFCE Revisited: Validity Before Recommendation.

Central question

When does a generated counterfactual become a valid explanation?

A model can return an appealing candidate that does not produce the intended prediction. The thesis first measured this gap in UFCE, then moved the validity check before candidate selection and carried the same release rule into a natural-language interface.

Evidence boundary

Track 1: five tabular binary datasets, UFCE1/2/3, logistic-regression targets and filtered candidate selection.

Track 2: a Bank Loan natural-language handoff with a deterministic verification core. Controlled tests, not a real-user evaluation.

Retrospective: historical 2026 thesis experiments; no new model training performed for this article.

In brief

This master's thesis (University of Science, VNU-HCM, defended September 2026) reproduced UFCE user-feedback counterfactual explanations on five tabular datasets and found that some selected outputs, especially from UFCE2/3, did not actually flip the model's prediction.

Moving the validity check before candidate selection (UFCE-FF) makes target-label validity a condition for every released explanation. In controlled end-to-end tests, none of the 55 produced outputs was an invalid flip.

A natural-language interface lets a language model parse the user's request while a deterministic verifier decides what is released. No real-user study was conducted.

01 / Foundations

What is a counterfactual explanation?

01

A counterfactual does not merely describe which features matter. It asks what would have to change in an input for a model to return a specified alternative outcome.

Suppose a binary classifier rejects a loan application. A counterfactual explanation asks which allowable changes to the applicant’s features would make the same trained model predict approval. The outcome is model-relative: it is not a promise that a real institution will approve the application, or that every suggested change is ethically or practically acceptable. [2][3][6]

01

Target validity

The candidate must reach the user’s desired prediction f(x′) = y*. Small numerical distance cannot substitute for that condition.

02

Action constraints

A candidate must respect features that cannot change, allowed directions and requested bounds: x′ ∈ C(x).

03

Quality after validation

Only then do proximity, sparsity, plausibility and actionability become meaningful criteria for comparing usable alternatives.

Different methods search this constrained space differently. Wachter et al. formulate counterfactuals as minimal changes to alter a model decision; actionable recourse explicitly considers what can be changed; DiCE searches for diverse solutions. The 2024 UFCE method provides the starting point here because it incorporates user feedback into tabular counterfactual generation. [2][3][4][5]

Not one notion of validity

Prediction, admissibility and intervention are different claims.

The formal flip test answers a model-behavior question: does the fixed classifier predict the desired label for the candidate? Admissibility adds syntactic and policy constraints such as immutability, directionality, category domains and upper or lower bounds. Actionability asks whether a person could actually perform the proposed changes; causal or downstream feasibility asks what the intervention would do in the real world. Neither follows logically from a successful prediction flip. A counterfactual can be very close in feature space and still fail to represent a sensible action. [2][3][12][13]

EXPLANATIONWhich alternative input changes the model output?
RECOURSEWhich feasible intervention could reach the goal?
RELEASE GATEWhich generated candidates may the system present?

This distinction is essential for interpreting the thesis: the proposed intervention strengthens the last question. It does not provide a causal intervention model or solve global counterfactual search. That narrower contribution is measurable and falsifiable.

02 / Research landscape

Where this work sits in counterfactual XAI

02

The thesis draws on three strands of work that are related but should not be treated as interchangeable: generating alternatives, incorporating user constraints, and mediating explanations through natural language.

01 / Generate & benchmark

What alternatives can the model produce?

Counterfactual optimization, prototype-guided methods, feasible paths and diverse recourse provide different search and ranking strategies. DiCE emphasizes candidate diversity, whereas FACE and actionable-recourse formulations put greater weight on feasibility or available action paths. Benchmarks and reviews warn that proximity alone cannot carry a complete evaluation. [2][3][4][7][8][9][11][12][13]

02 / Incorporate the user

Which changes are permitted or preferred?

One-size-fits-all explanations can conflict with personal objectives. UFCE explicitly incorporates user feedback in tabular counterfactual generation; related work examines personalized explanations, human-in-the-loop recourse and user trust. These studies motivate user feedback, but their human-facing findings are not evidence from this thesis's own users. [5][15][16][17][18][19][20][21]

03 / Interface & validation

Who translates language into executable constraints?

Semantic parsing and structured language-model outputs offer a natural-language interface, but output schema compliance does not by itself establish semantic correctness. This motivates a bounded LLM parser followed by deterministic reconstruction, model-level flip verification and an explicit terminal state. [22][23][24][25][26][27][28]

Positioning: The contribution is neither a new counterfactual generator nor an LLM asked to reason out its own recourse. It is a verification-aware UFCE selection path plus a controlled natural-language handoff, evaluated as two connected experiments.
03 / Research framing

The audit question: is the returned output actually valid?

03

The thesis began by reproducing UFCE, then asked a narrower question: does a solution selected by the public reference path still produce the intended label when checked again?

A benchmark table can report attractive proximity or sparsity even if a selected candidate does not flip the prediction. This creates an evaluation-level category error: the quality of a returned vector is being described as the quality of a valid counterfactual before validity has been established.

01

Reproduction: what does the publicly available UFCE path return across its three variants and five tabular datasets?

02

Verification: how many selected outputs reach the desired label, and can already-generated valid candidates be retained by filtering before selection?

03

Handoff: can natural-language feedback be converted into constraints without giving an LLM authority to invent or approve the final counterfactual?

The resulting study has two connected tracks rather than two unrelated projects. Track 1 establishes a reliable release gate at the generator boundary; Track 2 tests whether an interface can feed user constraints through that same gate. The work is a master’s thesis retrospective, not a claim to introduce an entirely new counterfactual search algorithm.

RQ1 · FIDELITY

Does a selected UFCE output satisfy the target-label condition?

Distinguish published UFCE results, a reproduction's selected output, and the output after an explicit post-hoc flip check.

RQ2 · SELECTION

Can validation before selection recover usable candidates already present in the candidate set?

Quantify query coverage and the resulting trade-offs in proximity, sparsity and the three APF quality metrics.

RQ3 · HANDOFF

Can natural-language feedback be conveyed without transferring verification authority to the LLM?

Separate JSON/schema readiness, exact reconstruction, successful UFCE-FF execution and release of verified counterfactuals.

04 / Method

Why move the flip check before selection?

04

UFCE-FF preserves the candidate generator and changes the admissible set seen by the selector. A post-hoc validator and a pre-selection filter ask different questions.

Let Aₖ(x) be the candidate set explored by UFCE variant k. The reference selector may return S(Aₖ) even when that candidate does not flip the model outcome. A post-hoc check evaluates the already-selected output; it cannot rescue an alternative that was present in the candidate set but not chosen.

REFERENCE + POST-HOC CHECK
UFCE generates Aₖ
↓
Select S(Aₖ)
↓
Check target flip afterward

May reveal that the reported candidate is invalid. It does not change which candidate was selected.

UFCE-FF · PRE-SELECTION GATE
UFCE generates Aₖ
↓
Keep only Vₖ passing the gate
↓
Select S(Vₖ) or stop

Every released candidate must pass the original model’s target-label check and applicable hard constraints.

FILTERED CANDIDATE SETnot a new generator
Vₖ = { x′ ∈ Aₖ  |  f(x′) = y*  ∧  x′ ∈ C(x) }

The novelty is a change in selection and release semantics, not new search capacity. Valid alternatives may be farther away: restoring a previously unselected target-flipping candidate can improve coverage while worsening proximity or sparsity. [5][5][13]

Formal research contract

One validator, two different places in the control flow.

Published-path output

Ak = Gk(x,u,K);   zpub = S(Ak)

Post-hoc: evaluate f(zpub)=y* only after the selector has committed to the candidate.
Verification-first output

Vk = {z ∈ Ak : f(z)=y* ∧ z∈C(x)}

UFCE-FF: if Vk is nonempty, choose S(Vk); otherwise terminate with no_valid_cf.
PSEUDOCODE / VERIFICATION BEFORE SELECTIONA fixed candidate generator
candidates = UFCE_k.generate(x, feedback, config)
verified   = []
for z in candidates:
    if model.predict(z) != target_label:
        audit.record(z, "non_flip"); continue
    if not satisfies_hard_constraints(z, x, feedback):
        audit.record(z, "constraint_blocked"); continue
    verified.append(z)
if not verified:
    return no_valid_cf, audit
return selector(verified), audit

Importantly, the published reference implementation includes local label checks inside some UFCE functions; the thesis does not claim that UFCE never checks labels. Its operational criticism is narrower: the terminal selected output was not universally guaranteed to flip when reevaluated on the locked reproduction path. [5][7]

Pre-selection filtering does not enlarge Ak. If the original selected candidate is invalid but a valid alternative already exists, the chosen result may move farther from x; if none exists, output becomes a meaningful no_valid_cf instead of an unchecked recommendation.

06 / Empirical finding 1

A selected candidate is not necessarily a counterfactual

06

The striking result is not a single average distance. It is the difference between a candidate being returned and the prediction actually changing to the requested class.

Across the five datasets, the reproduced UFCE1 path was generally more stable, while UFCE2 and UFCE3 showed substantial differences between selected outputs and verified flips. The most extreme case was Movie: the selected-output validation found 0/126 target flips for both UFCE2 and UFCE3. Graduate Admission showed only 7/56 verified flips for each of those two variants.

What improved

Previously hidden valid options become selectable.

On Bank Loan, the observed UFCE-FF coverage was 80/250, 44/250 and 26/250 across variants 1–3. Coverage for FF2 and FF3 can exceed the number of initially selected outputs that flipped because the filter changes which candidate can be chosen.

What did not improve

The candidate pool remains the ceiling.

Movie UFCE-FF2 and UFCE-FF3 still found 0/126 valid solutions. A correctness gate can prevent invalid release; it cannot create new candidates or repair a collapsed search variant.

Graduate Admission provides a complementary case: only 7/56 already-selected outputs passed the UFCE2 and UFCE3 post-hoc check, while pre-selection filtering could recover additional query coverage by selecting from existing valid alternatives. The resulting solutions were often farther from their origins. Success rate and solution quality therefore need to be reported together.

Bank Loan · UFCE220 → 44

Twenty of 250 previously selected UFCE2 outputs flipped. Under the verification-first run, 44 queries had a releasable candidate. This is evidence for a selection gap in the measured workflow, not evidence that the generator's search area expanded.

Graduate · UFCE37 → 45

Filtering before selection recovered valid-query coverage, but the FF-only cases were more distant on average. The historical query-level analysis reported 12.87 mean Euclidean distance for 38 FF-only cases versus 3.35 for seven cases valid under both paths.

Movie · UFCE2/30 / 126

The release gate could not rescue these variants: it cannot invent a target-flipping alternative when the explored pool supplies none. In contrast, UFCE1 retained coverage on 125 of 126 queries.

Important interpretation: Graduate FF2/FF3 and Bank Loan FF2/FF3 are useful positive examples, but the aggregate selected-valid and FF counts do not form a perfect set inclusion relationship across all reported artifacts (BUPA FF1 is the visible exception). The correct conclusion is about each path's measured coverage and its selection contract, not an unverified query-by-query identity between runs.

07 / Empirical finding 2

Correctness changes how quality metrics should be read

07

Validity is a prerequisite, not the entire objective. Filtering invalid candidates can change which examples enter the metric average and which solution each query receives.

After a flip gate, nearest-neighbor selection can prefer a different, valid but more distant candidate. A larger Euclidean distance in that case is not automatically a regression in the user’s objective; it can be the cost of making the reported recommendation truthful to the model. Conversely, a very small distance is not automatically a usable intervention.

The conditional DiCE/AR comparisons showed that UFCE-FF could be competitive on proximity and sparsity in several settings without dominating Actionability, Plausibility and Feasibility universally. On Bank Loan, a particularly easy model boundary involving a binary banking feature illustrated why proximity should not be confused with practical recourse. [3][4][4]

Interpretation rule

Never plot solution quality without the denominator: Who received a verified solution? Otherwise a method with very few successes may appear excellent simply because its hard cases have disappeared from the plotted sample.

Comparison under matched conditions

UFCE-FF against DiCE and actionable recourse

DiCE and actionable recourse (AR) serve as conditional reference methods rather than claims of a universal leaderboard. Comparison is meaningful only at matched dataset, predictor, preprocessing, evaluated queries and metric definition. In particular, the tabular comparison below reports quality among produced solutions; coverage is reported separately. [3][4][8][11][12]

Graduate supplies a positive counterexample to the assertion that a flip gate always destroys solution quality: under these operational metrics, FF1 retains relatively high APF while changing fewer features. Yet that observation does not license generalizing the ranking to every dataset or method configuration. For Bank Loan, FF2 and FF3 preserve much lower coverage than FF1, and a binary banking feature can dominate the model's prediction change without becoming a reasonable recommendation to a person.

The most instructive case is Bank Loan. A candidate may cross the logistic decision boundary through changing a binary account feature while registering a tiny Euclidean distance on continuous variables. The thesis explicitly flags the CDAccount example: numerical closeness must not be equated with a realistic or ethically acceptable personal intervention. It is a dataset-specific diagnostic, not a universal behavioral explanation.

On Graduate, the FF1 one-feature solution is relatively close and sparse, while FF2 and FF3 exhibit a pronounced quality–coverage trade-off. On Movie, the extreme sparsity of FF1 is impressive conditional on success; FF2 and FF3 have no solutions to characterize. Reading a quality table without the coverage table would therefore produce a misleading method ranking.

Selection-induced change in the evaluation cohort

Once the acceptance gate is introduced, the set of observed valid solutions changes. A favorable per-solution average can coexist with poor overall coverage; a farther valid alternative can be preferable to an invalid nearby point. Report both the coverage denominator and the conditional quality before interpreting a gain.

08 / Natural-language handoff

Let the language model parse; let the verifier decide

08

The second track extends the same release discipline to user feedback: an LLM can translate a request into structure, but it is not the authority that validates or invents the recourse.

A person may state constraints informally—“keep this attribute unchanged”, “do not increase this value beyond the range”, or “only change one feature”. A language parser can normalize these statements into a typed request with field evidence. Deterministic components then check schema, value ranges, conflicting instructions and data semantics before constructing an UFCE-FF request.

Separately, a small bilingual parser check involved eight English and eight Vietnamese scenarios repeated three times. Its high scores are a check of designed cases, not evidence of general-purpose language understanding. The final acceptance condition still depends on the original predictive model and typed user constraints, not parser confidence.

Why this is a hybrid XAI interface

A language model does not own model truth.

The parser maps natural-language utterances into a typed request with field_evidence, canonical feature names, values, status and constraints. The deterministic handoff then verifies both the structure and the semantics of that request. The local research configuration used Qwen3-14B Q4_K_M for bounded parsing, not for constructing candidate counterfactual vectors. The parser's input/output contract is intentionally smaller than an open-ended dialogue agent. [22][23][26][27][29][31][32][33][34]

Examples of deterministic semantics include reconciling annual Income with monthly CCAvg, normalizing currency under the study's fixed conversion convention, refusing an unsupported Education category and rejecting contradictory instructions rather than fabricating values. They are examples of field-preserving parsing and domain validation, not evidence of generalized natural-language understanding.

The thesis positions the LLM as a parser and handoff interface. Whether a discovered candidate is a valid counterfactual is decided by the fixed classifier and deterministic constraints; whether the language model can explain an accepted solution persuasively to a real person was not evaluated by a human study. Where 250 natural-language requests were lost

09

The handoff experiment tests whether structured source records survive conversion to natural language and back into a UFCE-FF request. It is not the same test as the 200-session harness.

233/250 is the final exact-reconstruction acceptance count, not 243/250. The 243 cases passed the earlier operational-readiness gate; ten more were rejected on exact semantic reconstruction. This distinction is easy to lose when reporting only the JSON-valid share.

Effect on verified coverage

The interface incurs an observable retention cost.

The loss is concentrated in upstream interpretation and acceptance, not in a newly trained counterfactual generator. Once a request clears the handoff, UFCE-FF retains the same target-label release rule. This is a bounded-interface feasibility study, not a claim that a language parser makes recourse universally available.

Separate small parser diagnostic: The selected local parser was also tested on eight English and eight Vietnamese cases, each repeated three times (24 runs per language). Success across that designed set is an operational smoke test; repeated runs do not create 24 independent linguistic scenarios or establish population-level reliability.
10 / End-to-end evidence

What happened across 200 controlled sessions?

10

A separate 200-session harness evaluated how the complete feedback-to-counterfactual pipeline terminated. The central observation is a trade-off between strict release validity and limited generation coverage.

Session outcomes · independent controlled harness

200 sessions, three terminal groups

Bank Loan
55 / 200Verified counterfactual found
4 / 200No recourse needed

All 55/55 released counterfactuals passed the desired-label flip check. Within the subset with active user constraints, 28/28 released outputs also satisfied those constraints and downstream feasibility checks. This is conditional release validity, not a 100% chance of finding a solution.

Of the 141 other terminal states, 140 were classified as no_valid_cf and one as constraint_blocked. The prominent failure mode was a lack of generated acceptable candidates, not a license for the LLM to improvise a response. Some alternative solutions may exist outside the generator's explored region.

The 200-session harness and the 250-query reconstruction evaluation are independent test contracts. Their counts must not be summed into a single funnel or compared as though they share the same denominator.
Failure diagnosis

Does no_valid_cf mean the desired alternative does not exist?

No. The 140 no_valid_cf sessions are a terminal state of the explored generator path, not an impossibility theorem. A separate logistic-model diagnostic searched the formally constrained domain and found an alternative reaching the target label in 127 of those 140 sessions. For the other 13, the diagnostic found no such alternative inside its tested domain. The check is a separate diagnostic reference: it does not prove exhaustive recourse over the entire data space and does not mean the UFCE generator would have found those alternatives by widening the result cutoff.

127 / 140Alternative found by diagnostic checkerCandidate-search headroom is observable.
13 / 140No alternative found in checked domainNot proof of global infeasibility.

This result changes the interpretation of the apparent contradiction between 55/55 valid released candidates and 140 sessions with no valid candidate found. The control boundary was effective when it released a result; search capacity was the bottleneck for many sessions. These are two independent engineering requirements and neither can substitute for the other.

SUCCESS PATH

Counterfactual found

Input is reconstructed, a candidate reaches the target prediction, constraints are passed, and the result is released with the verified status.

BLOCKED PATH

Constraint blocked

User constraints disallow generated alternatives. The interface reports the stop reason instead of relaxing the rule or manufacturing a replacement.

NO ACTION NEEDED

Desired label already present

The original input already meets the target; the system reports no_recourse_needed rather than recommending an unnecessary change.

11 / Discussion

What the thesis established—and what remains unresolved

11

Two engineering claims survived scrutiny: model-output validity needs to be checked before release, and natural-language feedback can be handed off to a deterministic verifier without granting the LLM control over truth.

Supported conclusion

Correct by construction at the release boundary

The pre-selector gate makes target-label validity an explicit condition for every candidate it releases. The controlled end-to-end tests observed no released invalid flips among the 55 produced outputs.

Unresolved question

How to find enough acceptable candidates

When no valid candidate was explored, the filter cannot help. Better search, adaptive neighborhoods and candidate augmentation must be evaluated separately from the verification gate.

Supported observation

Reproduction and post-hoc validity are different layers

Selected outputs from the reproduced UFCE paths could look numerically appealing yet fail the target flip, especially for UFCE2/3 on some datasets.

Unresolved question

Whether people accept these explanations

Schema adherence and deterministic checks do not measure user trust, comprehension, perceived fairness, causal plausibility or real-world feasibility. No genuine user study was conducted.

Nor does the study show that UFCE-FF outperforms DiCE or actionable recourse universally. It demonstrates a narrower but important design property: an interface should not treat a candidate vector as an explanation until the release conditions have been verified. [3][4][5][18]

Contribution versus open research

What can be generalized—and what cannot?

The strongest thesis contribution is an evaluation discipline, not a universal performance claim: (i) a candidate is not a verified counterfactual until the predictor reaches the target; (ii) a post-hoc pass/fail cannot replace pre-selection filtering when the generated pool contains alternative valid solutions; and (iii) a natural-language interface can preserve these gates through typed reconstruction and safe termination.

Several plausible future directions require independent experiments. Search expansion or adaptive neighborhood search could address missing valid candidates, but would change the generator and must be compared under a fixed validity contract. Multi-class extension would require precise target-class semantics and updated experiment reporting; the present thesis results are for binary classification. A human-centered evaluation would test comprehension, trust and actual usability rather than using operational proxy checks as substitutes. [6][14][17][18][19][20][21]

The distinction between plausibility in the system tests (schema/domain checks) and a formal causal or distributional plausibility metric should remain explicit. Likewise, parser repeatability and 55/55 conditional validity should never be presented as an externally validated 100% end-to-end success probability.

12 / Key takeaways

What worked, what still falls short

12

The result is neither “UFCE solved” nor “counterfactual search failed.” It is a more precise separation between output verification, candidate availability and the interface that conveys constraints.

+
Evidence-supported strengths

What worked

01

Validity became a release condition.

UFCE-FF places the flip gate before selection, avoiding the interpretation of unchecked selected outputs as valid counterfactuals.

02

Previously unselected valid candidates could be recovered.

On Bank Loan, FF2 and FF3 achieved 44/250 and 26/250 valid-query coverage, respectively; these differ from the validity of their originally selected outputs.

03

The language interface stayed bounded.

The 250-query handoff achieved 233 exact reconstructions; all 55 released results in the separate 200-session harness passed the target-label check.

−
Limits worth preserving

What still falls short

01

Verification does not create recourse.

Movie UFCE-FF2/3 found zero acceptable candidates in 126 queries; 140/200 controlled sessions ended in no_valid_cf.

02

Correctness is not the same as practical actionability.

Closer and sparser results did not automatically dominate DiCE/AR in plausibility, feasibility or actionability.

03

Controlled tests are not user validation.

The thesis core evaluated five binary tabular datasets; a separate defense-appendix experiment tested one three-class student dataset. Generalization beyond that setting, human trust and real-world deployment remain untested.

The durable lesson

Verification is part of the explanation, not a final cosmetic check.

The important boundary is not where a counterfactual-looking vector is produced. It is where a system decides whether that vector is allowed to become an actionable recommendation. UFCE-FF makes that decision explicit; the natural-language handoff preserves it.

Most important next experiment: hold the same queries, predictor and hard-constraint contract fixed, then augment or adapt the candidate generator and measure both query coverage and conditional quality. An independent human study belongs to a later validation tier, not as a substitute for those mechanistic tests.

Appendix A / Native multiclass verificationUCI Student Outcomes · 3 labels

In multiclass prediction, a flip is not necessarily the target.

Binary UFCE commonly checks whether the candidate changes the predicted class. A native three-class classifier needs a stricter test: a Dropout → Graduate request cannot accept a candidate predicted as Enrolled. The release gate checks the specific requested target and the actionable-feature policy.

Appendix B / Offline MI sensitivityUPV-2025 · train-reference size

How expensive is pairwise MI precomputation at scale?

UFCE-FF2/3 use feature-pair priorities derived from mutual information (MI). The scalability concern is the cost of ranking many eligible feature pairs when the reference training table grows. This diagnostic compared MI precomputation on three training-reference sizes, separately from counterfactual generation.

29 mutable features  ⇒  C(29, 2) = 29 × 28 / 2 = 406 feature pairs

UPV-2025 has 464,739 records and 81 raw input features; the group-wise training partition contains 325,483 records. Under the tested policy, 28 numeric features and one dedicacion category were mutable. For each eligible pair (i, j), the experiment estimated I(Xᵢ; Xⱼ) on train-only encoded references using scikit-learn mutual_info_regression (version 0.24.2, random_state=0) and ranked pairs by estimated MI. Eight workers distributed the 406 independent calls.

What this answers—and what it does not. Numeric-pair ranking was reasonably stable across these references, but the five pairs involving dedicacion were not (only 1/5 overlapped with 10k). The categorical variable was ordinal-encoded and treated by the estimator as continuous, limiting the categorical MI interpretation. The 131.08 s figure is offline wall time for all 406 calls together, not per-query latency; the experiment did not report peak RAM. The MI test did not produce new counterfactuals or measure their coverage. The larger UPV predictive-model snapshot also carried an original STOP convergence gate, so downstream exploratory CF results should not be promoted to a validated benchmark.
